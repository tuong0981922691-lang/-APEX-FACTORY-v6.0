# REUSABLE_ASSETS

## Scope

This register retains only knowledge patterns stated in domain-neutral form. A transferable asset is a method or control that can be adapted across future knowledge ecosystems; it is not an assumption that every field should use identical thresholds or procedures.

## Reusable assets

| Asset | Reusable form | Evidence / status |
|---|---|---|
| Evidence labels | Separate FACT, INFERENCE, UNKNOWN and retain provenance | **FACT:** Repeated across the seed sources. **INFERENCE:** Minimum metadata for knowledge records. |
| Human authorization | Require accountable approval before consequential action | **FACT:** Documented as a gate. **INFERENCE:** Calibrate to impact and reversibility. |
| Evidence verification | State claim/criteria, check provenance, validate, compare with observed result | **FACT:** Framework and candidate procedure. |
| Decision states | Accept, revise, reject, hold/UNKNOWN | **FACT:** Outcomes are documented. **INFERENCE:** Record rationale and permitted next transition. |
| Audit lineage | Link input, evidence, evaluation, authority, action, result, and review | **FACT:** Durable traceability is a repeated principle. **INFERENCE:** Use linked, versioned records. |
| Failure classification | Separate incident, modeled error condition, forecast risk, and unknown | **FACT:** Explicit caution in failure sources. |
| Staged change | Bound scope; verify; authorize; expand gradually; retain recovery option | **FACT:** Staging/pre-impact checks are referenced. **INFERENCE:** Exact sequence must adapt to context. |
| Progressive review | Broad scan → risk identification → evidence-backed claim review | **FACT:** Progressive-depth review is documented. |
| Learning from outcomes | Compare intended and observed results; verify explanation before updating knowledge | **FACT:** Evidence-based learning is stated. **INFERENCE:** Review/version updates. |
| Capability graph | Model functions, inputs, outputs, dependencies, and evidence separately from agent identity | **FACT:** Sources caution against inferring autonomous agents from functions. |
| Knowledge atomization | Give each claim an ID, description, evidence, source, and relationships | **FACT:** Graph schema is specified in source artifacts. |
| Prompt scaffolds | Bounded-source investigation, decision reconstruction, audit, reverse analysis, failure review, and learning review | **FACT:** These candidate templates are supplied. **INFERENCE:** They require validation in a target environment. |

## DOMAIN_SPECIFIC

**FACT:** The five authorized migration sources require domain removal but do not enumerate a complete list of domain-bound atoms or examples.

**INFERENCE:** Any term, threshold, taxonomy, heuristic, or example whose meaning depends on a particular field must be tagged `DOMAIN_SPECIFIC` until an explicit domain-neutral mapping is reviewed. Do not migrate it as a universal rule by simply renaming it.

**UNKNOWN:** No specific item can be reliably classified here beyond this rule without going outside the allowed five inputs. This register therefore names no field-specific examples.

## Adaptation rule

**FACT:** The seed sources say portable principles still have unresolved target-specific thresholds, owners, schemas, and implementation status.

**INFERENCE:** Reuse the structure, not unvalidated parameters: preserve evidence labels, gates, provenance, and decision states while defining criteria and authority anew for each ecosystem.

**UNKNOWN:** What adaptations each future field will require.
