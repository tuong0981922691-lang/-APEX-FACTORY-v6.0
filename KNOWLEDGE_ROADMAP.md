# KNOWLEDGE_ROADMAP

## Roadmap boundary

This roadmap orders knowledge curation based only on the five authorized migration artifacts. It is not a software implementation plan, approved SOP, or authorization to investigate additional sources.

## NOW — establish safe seed layer

- Import the nine seeds from `KNOWLEDGE_SEEDS.md` with stable IDs, evidence, related nodes, and confidence rationale.
- Register the eight knowledge packs, retaining one canonical seed per ID rather than duplicating content.
- Import the nodes/relationships in `MASTER_KNOWLEDGE_GRAPH.md` as conceptual edges; label inferred edges.
- Preserve FACT / INFERENCE / UNKNOWN and mark all procedures/prompts as candidates.
- Record the absence of evidence for a fixed agent count and autonomous meta-brain as UNKNOWN, not as a negative universal claim.

**FACT:** These assets and distinctions are present in the authorized input documents.  
**INFERENCE:** This is the lowest-risk first migration because it preserves epistemic status and lineage before operationalization.  
**UNKNOWN:** Target import schema, owner, and acceptance checks.

## NEXT — review before operational use

- Have the future knowledge owner review candidate frameworks, procedures, prompts, confidence levels, and graph relationships.
- Define decision owners, acceptance criteria, thresholds, exceptions, audit access/retention, and update approval only when the destination context supplies evidence and authority.
- Validate prompt candidates on representative tasks before marking them reusable defaults.
- Review `DOMAIN_SPECIFIC` quarantine tags and approve only mappings that preserve meaning.
- Confirm whether capability nodes map to actual agents; do not create or assert a multi-agent structure from the conceptual graph alone.

**FACT:** The source materials leave these operational details or validation status unresolved.  
**INFERENCE:** Review is required before candidate material becomes active policy or routine.  
**UNKNOWN:** Reviewer identity, validation dataset, and approval process.

## LATER — expand only when authorized evidence exists

- Add verified outcomes and postmortems with evidence lineage; derive new lessons only after root cause review.
- Refine confidence/evidence grades if the receiving system needs distinctions beyond the three-state taxonomy.
- Expand the graph with tested relationships, ownership, versions, and lifecycle states.
- Reassess cross-pack duplication and retrieval quality after actual use.
- Revisit unresolved architecture and coordination questions only if separately authorized research becomes available.

**FACT:** The source artifacts call for verified learning but do not establish automatic adaptation or a target runtime.  
**INFERENCE:** Later expansion should be evidence-triggered rather than speculative.  
**UNKNOWN:** Timing, system behavior, effectiveness measures, and any future discoveries.

## Stop conditions

**FACT:** Source evidence status must not be upgraded without support; candidates are not approved procedures.

**INFERENCE:** Pause migration of a claim when provenance is absent, meanings conflict, a domain-bound assumption remains, or a proposed policy lacks an owner.

**UNKNOWN:** The destination knowledge system’s formal quarantine and conflict-resolution policy.
