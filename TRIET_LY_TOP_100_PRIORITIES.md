# Triết Lý — Top 100 Knowledge Priorities

## How to read this list

The authorized files establish principles and gaps, not a validated ranking of business value. The ordering below is an **INFERENCE** prioritization for safe knowledge-base maturation. Each item is a proposed curation/review action, not a claim that an operational control already exists. Horizon tags: **NOW** = first 3 months; **NEXT** = 3–12 months; **LATER** = 12–36 months.

## Epistemic integrity and provenance

1. **NOW** — Preserve FACT / INFERENCE / UNKNOWN on every knowledge object.
2. **NOW** — Require a source reference for every factual claim.
3. **NOW** — Keep confidence explicitly qualitative unless calibrated evidence exists.
4. **NOW** — Preserve original stable IDs when reorganizing objects.
5. **NOW** — Record whether evidence is direct, summarized, or inferred.
6. **NOW** — Mark absent evidence UNKNOWN rather than treating it as negative evidence.
7. **NOW** — Separate evidence about a principle from evidence that it is operationally used.
8. **NOW** — Keep source boundaries attached to each review and conclusion.
9. **NEXT** — Define a target-context evidence standard before admitting new factual claims.
10. **NEXT** — Review conflicting sources without collapsing disagreement into a single unsupported assertion.

## Decision and human authority

11. **NOW** — Keep proposal, evaluation, authorization, and action as distinct stages.
12. **NOW** — Preserve accept, revise, reject, and hold as distinct outcomes.
13. **NOW** — Treat missing required evidence as hold, not implicit acceptance.
14. **NOW** — Identify the accountable human authority before consequential use.
15. **NOW** — Record decision rationale and next permitted step.
16. **NEXT** — Define authority delegation and exception rules for one approved context.
17. **NEXT** — Define escalation and override records.
18. **NEXT** — Set retry and re-review limits where the context requires them.
19. **NEXT** — Calibrate approval rigor to impact and reversibility.
20. **LATER** — Review authorization outcomes for consistency and unintended bypasses.

## Verification and evidence quality

21. **NOW** — State the claim and acceptance criteria before reviewing evidence.
22. **NOW** — Inspect provenance before relying on an output.
23. **NOW** — Identify which checks are required and which are absent.
24. **NOW** — Compare claims with observed artifacts or results where applicable.
25. **NOW** — Record failed, incomplete, and inconclusive checks separately.
26. **NEXT** — Define baselines and thresholds for an authorized target context.
27. **NEXT** — Specify how independent checks are selected and documented.
28. **NEXT** — Establish a process for resolving conflicting evidence.
29. **NEXT** — Validate review prompts on representative authorized cases.
30. **LATER** — Compare verification reliability across reviewed cases before claiming effectiveness.

## Audit and traceability

31. **NOW** — Link each decision to its source input and applicable specification.
32. **NOW** — Preserve the evaluation and authorization record with the outcome.
33. **NOW** — Keep audit lineage append-only where the chosen record system supports it.
34. **NEXT** — Define minimum audit completeness for the destination context.
35. **NEXT** — Set retention and access rules with accountable review.
36. **NEXT** — Define integrity checks and correction/version history.
37. **NEXT** — Review privacy and restricted-data implications before operational records are added.
38. **NEXT** — Link action and observed result to the originating decision.
39. **LATER** — Assess whether records support reliable reconstruction by an independent reviewer.
40. **LATER** — Retire or archive records only under an approved policy that preserves necessary lineage.

## Failure and risk learning

41. **NOW** — Distinguish confirmed incident, modeled condition, forecast risk, and UNKNOWN.
42. **NOW** — Do not assign root cause without evidence.
43. **NOW** — Do not present a candidate failure mode as an observed event.
44. **NOW** — Preserve evidence that disproves or weakens a proposed cause.
45. **NEXT** — Define the incident lifecycle only for an authorized destination context.
46. **NEXT** — Specify severity categories from contextual evidence, not analogy.
47. **NEXT** — Review postmortems for source lineage and causal support.
48. **NEXT** — Connect verified failure lessons to affected knowledge objects.
49. **LATER** — Track whether corrective changes prevent recurrence using suitable evidence.
50. **LATER** — Remove or downgrade lessons that fail later verification.

## Evidence status

### FACT

The authorized source set documents the underlying seeds, graph, frameworks, reusable assets, and unresolved questions referenced by these priorities.

### INFERENCE

The 100 actions order known gaps from epistemic integrity and authority toward validation, measured learning, and cautious expansion. The ranking and horizons are proposed, not source-validated.

### UNKNOWN

The available sources do not establish resource allocation, responsible owners, domain priority, quantitative success targets, or expected benefits.
